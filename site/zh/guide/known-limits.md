# 已知限制

装任何东西之前先读这一页。下面每一条都是预览包的真实边界,不是路线图上的待办——API 面冻结在
[`sdk/api.def`](https://github.com/loficore/Neo-Stellaris/blob/main/sdk/api.def)
声明的范围内,而没有实机读数的部分会明确标成「未证明」,而不是先许诺。

## DLL 是 Debug 构建

出货的 `stellaris_quickjs.dll` 用编译器的 Debug 模式构建,因为本项目所有实机读数都是对着**恰好
这份**字节取的。换成 Release 构建,「我们出货的字节」就不再是「我们验过的字节」,那要再花一轮实机
门,却换不来任何用户可见的收益。

后果才是重点:**一次内部安全检查失败会 abort 整个游戏进程。** 宿主自己的不变量(类型检查、分配器
断言、越界检查)是编译进跑在 `stellaris.exe` 里的代码的,所以一次 trip 就是一次 `abort()`——走的是
整个游戏,不只是你的 mod。mod 抛 JavaScript 异常没关系:宿主只禁用那一个会话,游戏继续跑。宿主自己
trip 了安全检查就不是。

同一形状还带出两件事:DLL **只能注入**且永不被卸载,因为打过补丁的引擎对象会在 `FreeLibrary` 之后
跳进未映射的页面。不要试图卸载它。

## 标记(flag)还没有实机读数

`System.setStarFlag` 与 `System.hasStarFlag` 在契约里,围绕它们的构建期门也是真的:`neo check` 会
拒绝计算出来的标记名,也会拒绝与官方 keyword 大小写不敏感撞名的名字。

**没有**被证明的是运行时行为。两次实机读数显示写入成功、而官方 `has_star_flag` 触发器一次都没
命中、存档里也什么都没有之后,标记键空间被重新静态推导了一遍。宿主现在经引擎自己的标记名表解析
名字(一个 `u16` id),而不是词法 token 表(一个 `u32` id)——那两个数字永远不可能相等,而这正是那
两次读数测到的东西。

所以,今天:

- 写入**可能**注册一个新名字(脚本写同一个字面量时引擎就是这么做的),而读取**永远不**注册任何东西;
- 标记表里没有 id 的名字读出 `false`,并记 `reason=no_flag_token`;`0xFFFF` 与 `0` 是硬失败,永远
  不算成功写入;
- 名字是 1–15 个小写字节,且必须是字符串字面量。

把这两个标记调用当成**未证明**:依赖它们的 mod 可以过所有离线门,仍然可能在官方脚本路径上看不到
那个标记。

## 国家作用域是只读的,方向也只知一半

`onCountry` 与 `Country.opinionOf` / `Country.theirOpinionOf` 读引擎好感矩阵的一个 `int32` 格。
**没有写入口**:这一格是惰性填充的缓存,填它就是往引擎状态里写,所以 `Country` 没有 setter。

读这一侧有两条边界:

1. `opinionOf` 与 `theirOpinionOf` 读的是**同一矩阵里互为转置的两格**——这一点是确定的——但哪一个
   才是「我们对他们的看法」并未确立。名字是引擎的 keyword,不是关于方向的断言。需要一个不依赖这个
   答案的值时,读对角线。
2. 值的单位与量纲没有独立参照:那个数字就是引擎自己的 `int32`,没有换算。

**id 口径**已经量到: C3 侦察记到 39 个国家,`scope+0x10` 的低 24 位落在 `0..39`、缺 23,所以宿主现在
先把 `SCOPE_ID_MASK` 套上,再把 `Country.id` 交给 bundle。好感**值**本身(两个方向)仍然没有实机读数。

国家这一侧其余的一切——资源储备、收入容器、能量索引——都不在契约里。

## 没有热重载、没有 Workshop、没有构建期脚本生成

- **没有热重载。** mod 文件在游戏启动时读;运行时那一半在宿主加载时读。改了 bundle 就要重启。
  (唯一的开发回路是:改 → `neo build` → 重装 → 重启。)
- **不是 Workshop mod。** 没有东西可订阅。`descriptor.mod` 那一半让引擎加载你的文件;`neo/` 那一半
  让宿主读你的 bundle。两半都由你自己分发。
- **没有构建期 TypeScript → `.txt`。** bundle 是宿主求值的 JavaScript,不是 Clausewitz 脚本文本。
  把前者转成后者是另一个产品决策,不是缺的功能。

## 不存在的作用域

只派发两种作用域:**system** 与 **country**。带着其它作用域来的派发只会被记下来然后丢弃:

```
NEO_SCOPE_OTHER mask=0x<mm> id=<n>
```

所以没有舰队、星球或人口作用域。也没有 **`onMonthly` 钩子**、没有全局 tick 钩子:每月驱动是
生成的 `on_action` → 隐藏事件 → `every_system` / `every_country` 这条链,也就是普通的官方脚本路径。

bundle 只会收到清单里声明的作用域。只声明 system 的 bundle 调用 `onCountry`,会记
`NEO_JS_REGISTER_REJECT … scope=country` 并保持惰性——会话不会被禁用。

## 刻意缺席的接口

`s.name` 与 `s.variable()` **不在**契约里。它们要等到各自的官方读路径被解析出来才谈得上;猜一个
native 名字比缺一个更糟,所以 `api.def` 不提它们,SDK 也不暴露。

## 宿主强制的限制

| 限制 | 值 | 触顶时会发生什么 |
|---|---|---|
| 上下文内存 | 16 MiB | 处理函数内部分配失败 |
| 栈 | 1 MiB | 同上 |
| 每次处理函数调用的时间预算 | 10 ms | 记 `NEO_JS_TIMEOUT`,**禁用该 mod** |
| JavaScript 异常 | — | 记 `NEO_JS_ERROR`,**禁用该 mod** |
| 并发运行时 mod 数 | 8 | 超过 8 个会被记一行日志拒绝;一个都没有则记 `NEO_JS_NO_MOD` |

禁用只针对**那个会话**:其它会话照常收到派发。每次都抛异常的 mod 会在第一次失败后被禁用,所以游戏
继续跑。

## 日志

`log(...)` 把 `NEO_JS_LOG <text>` 追加到 `C:/temp/neo_js.log`,**不是**官方 `game.log`。官方日志由
官方脚本那一半写(事件选项里的 `log` 效果)。

有用的行:

| 行 | 含义 |
|---|---|
| `NEO_JS_CALL` | 处理函数为某个作用域跑了一次 |
| `NEO_JS_WRITE … kind=variable` | 一次变量写走了官方函数体 |
| `NEO_JS_ERROR` | 处理函数抛异常;会话已禁用 |
| `NEO_JS_TIMEOUT` | 处理函数超过 10 ms;会话已禁用 |
| `NEO_JS_OPINION_REJECT … reason=<tag>` | 一次国家好感读取被拒绝 |
| `NEO_JS_FLAG_REJECT … reason=no_flag_token` | 标记名在标记表里没有 id |

## 离线门能证明什么、不能证明什么

`neo check` 在真实 QuickJS 运行时里对着 mock 宿主跑你的 bundle。它证明:bundle 类型正确、不含宿主
里没有的全局对象、恰好注册一个处理函数、过了标记名门、调 native 的形状与 `api.def` 声明一致。

它不证明:引擎会调你的处理函数、你读到的值就是预期的值、你的写对官方脚本路径可见,或者任何东西在
战役里真的能工作。这些问题由实机日志回答,不由一次绿色的 check 回答。

同样的切分适用于整个预览包:门是离线且机械的,而实机行为只能好到上一次真实读数那样。哪里缺读数,
这一页就直说,而不是先许诺。
